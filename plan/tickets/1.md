## What to build

A `check` feature, off by default, that implements the Check sections of
`rules/standards/errors.md`, `panics.md` and `logging.md` for every
consumer. It exposes one function:

```rust
pub fn rsb_errors::check::run(root: &Path, config: &Config) -> Vec<Finding>
```

`Config` names, relative to `root`, the `dispatcher` file (the one place a
`catch_unwind` is allowed), the `boundary` module (a file or directory, the
one place `warn!` and `error!` are allowed) and `ignore`, paths the check
does not enter (vendored code, this crate's own fixtures). `Finding` has
`path`, `line`, `rule` and `what`, and displays as one line
`path:line: rule: what` with `path` relative to `root`. `run` returns the
findings sorted by path and line; an unreadable file is a finding, not a
panic. Each consumer's `cargo xtask errors` calls `run` on its workspace
root and exits 1 on any finding.

The rules, one `rule` name each. "Tests" are files under a `tests/`
directory and lines after `#[cfg(test)]`; "main" is `main.rs` and
`src/bin/`; "`error.rs`" is a file of that name or a directory named
`error`. Comments and string literals are masked before matching, so a
pattern inside a doc example or a message is not a hit.

From `errors.md`:

- `banned-crate`: any `Cargo.toml` that lists `anyhow`, `eyre`,
  `color-eyre`, `failure`, `error-chain` or `thiserror` in a dependency
  table.
- `boxed-error`: a line with `Box<dyn ... Error ...>`.
- `variant-display`: a snafu variant with a `source` field whose display
  string lacks `{source}` or that has no display string.
- `variant-location`: a snafu variant with a `source` field that lacks
  `#[snafu(implicit)] location: Loc` (`rsb_errors::Loc` also accepted).
- `untyped-snafu`: `context(false)`, `Whatever`, `whatever!` or
  `snafu::Report` anywhere.
- `source-call`: `.source()` outside `error.rs` and tests.

From `panics.md`:

- `release-profile`: the root `Cargo.toml` without a `[profile.release]`
  that states `panic = "unwind"` and `overflow-checks = true`.
- `bare-panic`: `panic!()`, `unreachable!()` or `expect("")` with no
  message, outside tests. Tests are exempt because the standard's
  `clippy.toml` allows the missing messages there.
- `catch-unwind`: a `catch_unwind` outside the dispatcher file, the body of
  an `extern "C" fn`, and tests. Tests are exempt because every crate's
  `tests/error_line.rs` catches a panic to prove the hook.
- `extern-c`: an `extern "C" fn` with a body whose first statement does not
  call `catch_unwind`.

From `logging.md`:

- `print`: `println!`, `eprintln!` or the `log` crate (`use log`, `log::`)
  outside main and tests.
- `log-level`: `warn!` or `error!` outside the boundary module.
- `instrument-err`: `#[instrument(err)]` in any form, anywhere.

Text search over `.rs` and `Cargo.toml` files; no `syn`, no dependencies.
The walk skips `target`, hidden directories and `ignore`. The banned-crate
and boxed-error checks and their tests are lifted from lumen's
`xtask/src/errors.rs`, with `thiserror` replacing `snafu` in the list.

Tests live in `tests/check/` with one fixture tree per rule under
`tests/fixtures/`, each a minimal repository that is clean except for the
planted hit, so a test asserts the exact finding lines. One clean fixture
produces no finding, and one test runs `check::run` on this repository
with `tests/fixtures` ignored.

`README.md`'s `check::run` line and `engineering/errors.md` name the real
signature, and `engineering/errors.md` no longer says the crate never
checks itself. `Cargo.toml` gains the `[profile.release]` the standard asks
of every root manifest.

Seams: `check::run`, `Config`, `Finding`.

## Acceptance criteria

- [x] `cargo test --all-features` passes with one planted-hit test per rule listed above and one clean fixture.
- [x] `cargo build` without `--all-features` does not compile `check` or its dependencies.
- [x] `check::run` on this repository itself returns no finding.
- [x] `README.md` and `engineering/errors.md` name the real signature.
- [ ] CI is green on the PR.
