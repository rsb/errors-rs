## What to build

`Loc` prints ` (at file:line)` by default. Today it prints nothing until
the binary calls `show_locations(true)`, so the default error line names
each layer's operation and the reader needs a second run with `--debug`
to learn which line of code wrapped the failure. The reader of an rsb
error line is the owner at a terminal or an agent with one line of
context, and both want the file and line the first time. The owner
decided on 2026-10-18 that locations are on by default and the switch
turns them off.

- `SHOW_LOCATIONS` starts `true`. `show_locations(false)` turns the
  locations off for the places that want a stable string: a command
  reply that goes into an agent record, a test fixture, a golden file.
- The doc comments on `show_locations`, `locations_shown` and `Loc`, the
  crate docs and `README.md` say so. `README.md` also says why: the
  reasoning above, and that the default line is the one the standard's
  sample shows with its `(at ` segments.
- The binary's wiring in `README.md` becomes an off switch:
  `<APP>_ERROR_LOCATIONS=0` turns locations off; there is no flag to turn
  them on because they already are.
- `tests/error_line.rs` pins the exact line with locations off, then
  turns them on and asserts each layer gained an `(at ` segment. Same
  coverage, no line numbers hard-coded in a test.
- Version `0.1.1`, tag `v0.1.1`. The migration tickets pin that tag.

Nothing in `check` changes: no rule looks at the default.

## Acceptance criteria

- [ ] A two-layer error formatted with no call to `show_locations` contains one ` (at ` segment per layer, pinned by `tests/error_line.rs`.
- [ ] After `show_locations(false)` the same error formats as the exact line with no locations.
- [ ] `README.md`, the crate docs and `engineering/errors.md` state the default, the off switch and the reason.
- [ ] `Cargo.toml` is `0.1.1` and `check::run` on this repository returns no finding.
- [ ] CI is green on the PR.
